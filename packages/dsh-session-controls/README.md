# Session Guard

The composer-dock panel shows the active role, worker track, session activity and refusal reasons. It displays genuine empty or unavailable states. Status reads use an authenticated Remote; owner-only role and worker-track controls use separate mutation methods with confirmed Host readback. Track changes use compare-and-set revisions and do not change the lead model.

## Data and ownership

Host resolves the receiving Agent through the native agent lookup, so Remote access control checks the session resource. The status method reads the open dsh_governance_events domain for that session without opening stores, reading arbitrary paths, or exposing prompts or wire responses. Host and Client publish strict descriptors through the public Typert registry and mount APIs.

The direct Remote status projection uses the public core redaction leaf, covering all seven configured patterns before display truncation; it does not rely on the separate tool-result policy. Startup awaits Remote namespace mounting before exposing any slot or requesting state.

The UI theme uses DSH tokens and inherited system typography, with restrained semantic colors, visible keyboard focus, native filter controls, reduced layout on narrow screens and useful error/empty states.

## Incomplete functionality

Worker-track selection persists with revision checks, follows subagent creator ancestry and governs new facade dispatches. The worker guard checks admitted child identity and current policy at pre-step and llm/stream. Live model flows and in-flight cancellation have not been fully verified. Worker-tree aggregation, governance readiness across every subsystem and index controls remain incomplete.

## Verification

Native Host invocation/access control, descriptor mounting, slot rendering in the existing app URL, actual screenshots/layout, cleanup and restart must be checked before claiming this panel works. Browser context is not implicit. Client updates require the installed bundle and a refresh of the existing GUI unless matching rebuild/HMR behavior is verified. No replacement server is started.
