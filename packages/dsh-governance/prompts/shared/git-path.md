GIT PATH
The sandbox asks the user to confirm every git write once, and a chained command is confirmed once as a whole. So a run builds its history step by step but writes it in one confirmed command at the end:
- During the run, no git writes. Executors leave each unit's changes in the working tree and list every file they touched under Files changed.
- Keep the commit plan at `.kilocode/memory/<run>/commit-plan.md`: one line per verified unit, in integration order, with its files and its commit message. Two units that change the same file cannot be separate commits, because the first `git add` stages both changes; sequence the plan so each file belongs to one unit, or record that those units share one commit.
- When every planned unit is verified, dispatch one integration unit to the cheap executor whose brief is the single chained command: `git switch -c <branch> && git add <unit 1 files> && git commit -m "<unit 1 message>" && ... && git log --oneline -<n> && git push -u origin <branch>`. The user's one confirmation of that command is the approval for the commits and the push. Leave out the push when the repository has no remote or the task says not to push.
- The branch follows the project AGENTS.md scheme, default `remediation/<run>`, never `main`. The integration unit, as the executor of the run's last unit, appends one status TSV row per unit with its commit hash.
